[04/11/2026] - Hoàn thành BƯỚC 1: Cấu hình môi trường kiểm thử
1. Cài đặt các thư viện devDependencies cho `@thunderfood/web`:
   - `vitest` (v5.x): Test runner tốc độ cao tích hợp native với Vite.
   - `@testing-library/react` & `@testing-library/jest-dom`: Bộ công cụ render và kiểm tra DOM/UI.
   - `@testing-library/user-event`: Giả lập hành vi người dùng (click, nhập liệu).
   - `jsdom`: Môi trường giả lập DOM trình duyệt chạy trên Node.js.
2. Tạo các file cấu hình:
   - `frontend/apps/web/vitest.config.ts`: Cấu hình Vitest, alias `@/`, môi trường `jsdom`, load setup file.
   - `frontend/apps/web/src/test/setup.ts`: Tự động cleanup DOM sau mỗi test case và mở rộng matchers của jest-dom.
   - `frontend/apps/web/src/test/smoke.test.ts`: Test kiểm tra sức khoẻ môi trường (đã pass 2/2 tests).
3. Thêm scripts kiểm thử:
   - `frontend/apps/web/package.json`: thêm `"test": "vitest run"`, `"test:watch": "vitest"`.
   - `frontend/package.json`: thêm `"test": "npm run test --workspaces --if-present"`.
4. Lệnh chạy kiểm thử:
   - Chạy riêng web: `cd frontend/apps/web && npm run test`
   - Chạy chế độ watch (tự reload khi sửa code): `cd frontend/apps/web && npm run test:watch`
   - Chạy toàn bộ monorepo: `cd frontend && npm run test`

1. Đã triển khai 2 bộ Unit Test chuyên sâu:

      - Test `addToCart()` bắt lỗi khi món ăn hết hàng hoặc server lỗi.

   - Kịch bản 2: Khách vãng lai (CHƯA đăng nhập) bấm nút "Thêm vào giỏ" -> Kiểm tra hệ thống chặn lại, hiển thị Toast nhắc nhở và điều hướng sang `/login` (`mockNavigate('/login')`).

[04/11/2026] - Hoàn thành BƯỚC 4: Mock API tầng mạng với MSW (Mock Service Worker)
1. Cài đặt thư viện:
   - `msw` (v3.0.x): Chặn và giả lập request mạng ở tầng Network (HTTP layer) thay vì mock hàm code.
2. Thiết lập kiến trúc MSW:
   - `src/test/mocks/handlers.ts`: Khai báo danh sách các URL cần chặn:
     + `GET */v1/cart`: Trả về dữ liệu giỏ hàng chuẩn của ThunderFood.
     + `GET */v1/cart/count`: Trả về tổng số lượng món.
     + `GET */v1/products`: Trả về danh sách thực đơn món ăn.
     + `POST */v1/auth/login`: Xác thực thông tin đăng nhập, trả về JWT Token và User role.
   - `src/test/mocks/server.ts`: Khởi tạo server mock bằng `setupServer(...handlers)` từ `msw/node`.
   - `src/test/setup.ts`: Cấu hình vòng đời MSW:
     + `beforeAll(() => server.listen({ onUnhandledRequest: 'warn' }))`
     + `afterEach(() => server.resetHandlers())`
     + `afterAll(() => server.close())`
     + Cấu hình `axios.defaults.adapter = 'fetch'` để Axios tương thích hoàn hảo với bộ chặn mạng của MSW.
3. Các kịch bản kiểm thử trong `src/test/mswApi.test.ts` (4 test cases):
   - Kịch bản 1: Gọi `cartApi.getCart()` thật qua AxiosClient -> MSW tự động chặn và trả về đúng dữ liệu giỏ hàng mà không cần máy chủ Backend thật bật.
   - Kịch bản 2: Mô phỏng Server gián đoạn (Lỗi 500) thông qua `server.use(...)` -> Kiểm tra hệ thống bắt lỗi chuẩn xác.
   - Kịch bản 3: Đăng nhập thành công với tài khoản khách hàng hợp lệ -> Trả về token và quyền `CUSTOMER`.
   - Kịch bản 4: Đăng nhập thất bại (Sai mật khẩu) -> MSW trả về HTTP 400 kèm thông báo lỗi.
4. Kết quả thực thi:
   - 5 test files, 23/23 tests Passed 100% trong ~5.3 giây.

[04/11/2026] - Hoàn thành BƯỚC 5: Tích hợp CI/CD tự động hoá kiểm thử (GitHub Actions)
1. Kiểm tra cấu hình CI có sẵn:
   - File `.github/workflows/frontend-ci.yml` trước đó chỉ có 2 bước:
     + Bước 1: `npm run lint` (Chỉ kiểm tra format cú pháp với oxlint)
     + Bước 2: `npm run build` (Chỉ kiểm tra biên dịch TypeScript và đóng gói dist)
   - VẤN ĐỀ: Khi lập trình viên sửa sai logic giỏ hàng, tính sai tiền hoặc validation hỏng, mã nguồn TypeScript vẫn hợp lệ nên lệnh `npm run build` vẫn pass, khiến lỗi lọt lên production!
2. Nâng cấp workflow CI:
   - Đã bổ sung step chạy test tự động vào `.github/workflows/frontend-ci.yml`:
     ```yaml
     - name: Run Linter (oxlint)
       run: npm run lint

     - name: Run Automated Tests (Vitest)
       run: npm run test

     - name: Typecheck & Build Apps (Admin, Staff, Web)
       run: npm run build
     ```
3. Lợi ích đạt được:
   - Mỗi khi có commit mới (`push`) hoặc tạo `pull_request` vào các nhánh `main`, `master`, `develop`, GitHub Actions sẽ tự động chạy toàn bộ 23 bài test.
   - Nếu bất kỳ bài test nào bị lỗi (Fail), quy trình CI sẽ dừng ngay lập tức và chặn không cho merge code, bảo vệ tính ổn định cho ứng dụng ThunderFood.
